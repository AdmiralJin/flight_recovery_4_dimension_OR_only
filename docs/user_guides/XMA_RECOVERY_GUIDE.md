# 厦航数据恢复使用说明

1. 启动原工作台，在“数据设计”页面的“厦航数据与求解配置”中读取项目工作簿，或上传同格式七表工作簿。
2. 首次选“约20航班”，查看实际飞机、航班及联程数，再创建研究草稿。为保留飞机完整轮转，实际约20是30航班。
3. 默认目标选择“天池评分（数据包源码）”。也可独立选择 AIR 线性研究成本，AIR 参数在“成本”页编辑。调整该参数不会改变天池评分。
4. 初次建议直接联合优化、步长60分钟、最大延误120分钟、时限30秒，便于确认流程。最终研究需要扩大延误范围及加密候选，这一配置仅是可复现初始实验。
5. 编译通过后进入“实时求解”，创建快照并求解。算法可选择直接联合模型、小实例显式路径基准、联合子问题 Benders、Benders加列生成及分支定价。显式路径只适合小实例。
6. 结果区查看实际座位占用、旅客拆分、未服务人数、逐项天池成本和独立审计，或导出天池11列结果。未收敛时查看真实上下界；有审计通过的完整可行方案时可展示和导出，但不意味着已证明最优。

## 数据与结果含义

原 Excel 保留。窗口外航班固定在原飞机、原时间；缺少机组及维修信息，首版关闭这些模块。允许延误、取消、同机型换飞机、拆分改签及未服务。正常机场容量来源未给出，只有源码规则覆盖的机场限制参与求解。

人数按航段评分账本展示，同一人在中转和联程中可能出现在多个航段，不能把全表人数总和当作独立旅客数。终点是机型—机场全机队平衡，飞机个体可以换终点。

整飞机子集使用子集外进港航班的原时间作为中转边界，成本仅针对子问题。子集CSV不能直接交给原全量工作簿的JAR；官方评估必须使用完全相同的输入工作簿。

## 可复现实验

在项目目录运行：

```powershell
python scripts/benchmark_xma.py --sizes 20,100,500,2364 --seconds 30 --step 60 --delay 120
```

输出目录位于 `docs/codex_reports`，包括输入、结果、CSV、上下界、终止原因、列数、节点和进程峰值内存。遇分配规模超过上限可调整时间候选，或显式设置 `--max-assignments`。保护检查不会偷偷缩小实例。

原JAR复算（Java可执行路径需有效）：

```powershell
python scripts/verify_xma_jar.py --java java --workbook docs/codex_reports/xma_jar_validation_20261008/subset_fixture.xlsx --output docs/codex_reports/jar_repeat
```

正式实验应记录数据哈希、目标标识、候选参数和运行限制，比较两条路线时使用同一输入和限制。当前短时实验不能证明全量能快速求最优。
