# 厦航 HiGHS 首个可行解：运行与查看

本流程服务于 Workbench v3，先寻找满足航班、飞机与旅客约束的恢复方案，再在资源允许时扩大换机范围。小规模子集的结果不能拼接成全量可行解。

## 运行方式

- 默认双击实验目录中的 `start_xma.cmd`，按 Enter 开始。
- 已明确授权自动启动时，执行 `python scripts/xma_first_solution.py launch <实验目录> --start-now`，会打开可见 CMD 并直接运行。
- 三组任务串行执行：Q1（36 架飞机，6 小时）、H1（71 架，12 小时）、FULL（142 架、2364 航班，24 小时）。这是各组的最长预算，可能提前结束；等待资源的时间不计入预算。

## 模型与资源

采用 HiGHS 联合航班、飞机、旅客模型。取消人为 120 分钟延误上限，保留国内 1440、国际 2160 分钟的业务上限；恢复截止为北京时间 2017-05-10 21:40。先固定原飞机搜索，再逐步扩大同机型换机池。限制换机范围的模型给出的下界只适用于该阶段；通过独立审计的可行解才作为业务上界保存。

新批次可在 `prepare` 时用 `--memory-gib N` 设置进程树硬上限，内部模型预测准入额度取该值的 70%。默认硬上限为 6 GiB，启动门槛为 4 GiB；硬上限高于 6 GiB 时，启动前需有硬上限加 1.5 GiB 的可用内存。可用内存不足时批次自动等待，运行中触及系统紧急下限时守护器请求停止。仅运行全量任务可在 `prepare` 时加入 `--only FULL`。

## 查看结果与停止

- `state.json`：当前任务及运行状态，`waiting_for_memory` 表示已启动流程、正在等待内存。
- `summary.json`、`runs.csv`：各组完成后的汇总；全量成功看 FULL 的 `audit_pass`、`complete_decisions`。
- `jobs/<组名>/attempt_001/worker.log`：详细日志。
- 同目录 `checkpoint.json`、`flights.csv`：已审计方案及航班恢复表，找到首个方案后即可生成。
- `certified_optimal` 表示在当前候选范围内证明最优；有可行方案并不等于已经证明最优。全局下界、Gap 无法取得时保留为空。
- 缺少 Java 时官方评测记录为 `not_run`，独立业务审计结果仍单独保留。

关闭 CMD 会终止工作进程。需要有序停止时，可在实验根目录创建名为 `STOP` 的空文件，或按 Ctrl+C；恢复运行前移除 `STOP`。再次启动同一实验目录会读取已有结果，并扣除已消耗预算。

实验目录冻结代码、输入、校验哈希与校准记录，后续修改工作区代码不会改变已启动实验。
