# 厦航数据接入实施计划（执行版）

北京时间：2026-10-08T11:33:15

本项目位于 D:/python_project/flight_recovery，现有浏览器工作台、Python 后端和 AIR 四模块恢复模型已经提供草稿、快照、审计及分解求解流程。本次工作将厦航天池七表数据接入，扩展真实飞机座位、旅客拆分、机场规则及终点平衡，同时保留旧版 AIR 请求。天池数据包中的 Configuration.java、ResultEvaluator.java、InputData.java、Scene.java 是业务规则和成本的依据，天池目标和 AIR 成本配置独立选择。

## 阶段与交付

1. 梳理 HTML/公式注册表、实际联合模型和分解接口，记录代理约束与厦航差异。
2. 读取七表，保留字段、来源行及原文件哈希；编译时区、联程、中转、禁飞、过站和机场规则。
3. 独立实现天池逐项评分、AIR 线性研究成本及小实例显式飞机路径基准。
4. 实现飞机时间事件网络流与整数旅客分配的直接联合模型，接入工作台。
5. 实现联合飞机—旅客 Logic-based Benders、飞机路径列生成和逐节点定价的分支定价；使用有效条件割并报告真实上下界。
6. 验证小实例一致性，执行约20/100/500/全量规模实验，记录时间、解、界、列数、节点和内存；导出11列结果核对原JAR。

## 共同要求

保留完整飞机链和窗口外冻结上下文；子集是单独研究问题，保留外部进港中转原时刻，其成本不能冒充全量评分。原工作簿不修改。首版动作：延误、取消、同机型换飞机、拆分改签及未服务。机组和无依据的维修关闭。跨机型、提前、调机及联程拉直待后续扩展。

每个模型只对明确的离散候选集合声明最优。未收敛时保存合法 incumbent、上下界及终止原因。原模型请求兼容。每阶段总结写入本目录。
