# Workbench v3：HiGHS 直接求解基线

## 目的与模型

先验证完整数学模型能否直接求得合法方案、能否在限定时间内证明最优，再与 AIR 分解路线比较。本轮仅使用 HiGHS 求解，Gurobi 基线等待取得适用许可后另行登记。

- 公开输入：复用首次正式实验的 69 个冻结实例，保留原候选、成本、固定上下文、规则缺口及问题指纹。每例登记一个 `direct_mip`；不超过 12 班的实例另登记全路径 `integrated_oracle`，用于同问题对拍。
- `direct_mip` 使用原生 SolverAdapter 建立飞机有向无环网络流、航班选择、原始旅客组行程选择和容量约束，一次交给 HiGHS 求解；不枚举飞机路径，不调用我们组织的 Benders、列生成或分支定价。
- 厦航：按完整机尾选择约 20／50／100／500 班及全量，各自分别求解天池评分和 AIR 研究成本，记录闭包后实际规模。固定 30 分钟网格、最大延误 120 分钟；使用原有 `joint_arc_flow` 完整联合模型，显式指定 HiGHS。
- 厦航建模仍使用已安装的 gurobipy 线性表达式，再将同一个模型矩阵交给原生 HiGHS；不会调用 Gurobi 优化，也不会在计时中静默更换求解器。当前模型构建依赖本机可启动的 Gurobi 环境，不要求扩大 Gurobi 的求解规模许可。
- Delft 2019 仅有结果资料，没有可对应的完整输入，登记排除原因，不制造求解任务。公开模型仍关闭机组，不生成虚构机组或完整 Delft OD 需求。
- 本轮证据限定于冻结研究模型。与 ROADEF 原始评分、历史成绩的比较继续要求独立原规则证据。

## 时间与资源

`size-aware-v1` 建议策略同时考察实际航班、候选和分配组合数量，取三者最高档：

|档位|航班数上限|候选数上限|分配组合上限|单任务预算|
|---|---:|---:|---:|---:|
|0|12|100|1,000|600 秒|
|1|50|1,000|10,000|1,800 秒|
|2|100|5,000|100,000|3,600 秒|
|3|500|20,000|1,000,000|7,200 秒|
|4|超过上述边界|超过上述边界|超过上述边界|14,400 秒|

公开输入用候选数×飞机数估算分配规模，厦航登记时使用实际候选分配数量。界面尚未构模时可用保守候选估计；所有正式任务将具体预算写入冻结清单。建议不保证在时限内可行或最优，用户可手动调整界面预算；历史结果不改写。

预算包含算法内构模及优化，监护进程额外留 120 秒用于解释器启动、审计及落盘。解析、预检等时间另外保留；实际墙钟与求解时间分别记录，不将所有等待都计作求解器时间。首次求解器上界观测与首次经审计方案观测也分别保存。

单线程、MIP 相对 Gap 目标为 0。每个求解进程树内存硬上限 6 GiB。公开直接模型最多 100 万变量及 100 万约束；达到上限返回 `input_limit`，不截断后继续求解。厦航分配输入上限为 100 万，构模仍受总时间及进程树内存限制。保留超时、错误、资源限制、输入不支持及不可行记录。

本轮独立于此前的 AIR 正确性门槛和已消费的 24 小时实验预算。没有继承旧批次预算，也不会因 AIR 路线失败而跳过直接基线。每个任务的预算上限可能使整批持续数天；窗口显示该组登记时间上限，实际可提前结束。

## 分组与手动开始

```powershell
python scripts/highs_baseline.py prepare --previous .public_benchmarks/formal-v3-20261111-r4 --output .public_benchmarks/highs-direct-v3-20261112
python scripts/highs_baseline.py verify .public_benchmarks/highs-direct-v3-20261112
python scripts/highs_baseline.py launch .public_benchmarks/highs-direct-v3-20261112
```

创建四个 CMD 窗口：`micro`、`roadef`、`delft`、`xma`。各窗口先等待回车，再串行执行本组任务。回车前不启动求解子进程。多个组均回车时，通过操作系统文件锁协调，整台机器同一时间只执行一个本批次任务；等待资源不消耗该任务预算。这不阻止用户另外启动其他非本批次计算，正式计时应避免外部重负载。

关闭未回车的窗口不会启动任务。组已完成时不会覆盖证据；重新运行相同 `start_<group>.cmd` 并回车可继续尚未完成的任务。每次尝试保留独立目录。创建实验根目录下的 `STOP` 文件可停止派发并终止当前任务，保留已审计检查点；继续前移除该标记。取消、硬超时和进程异常不能变成“认证最优”。

## 复核与交付位置

输入、代码、环境、任务及预算冻结在 `manifest.json`、`registry.json`、`source/`、`inputs/`。`drafts/` 可导入 v3；配置页支持公开直接模型、小例 Oracle、AIR 主线，以及 HiGHS／Gurobi 选择和规模建议时限；厦航支持显式后端选择。

每次运行位于 `jobs/<ID>/attempt_<序号>/`，包括 `worker.log`、`events.jsonl`、`checkpoint.json`（存在合法方案时）、`evidence.json`、`result.json`。各组维护独立状态及 CSV，避免并发覆盖。全部结束后运行：

```powershell
python scripts/highs_baseline.py report .public_benchmarks/highs-direct-v3-20261112
```

生成完整 `summary.json` 和 `runs.csv`；仅对同一冻结问题的认证结果检查目标一致性。检查重点为方案独立审计、有效 LB/UB、界闭合、原始停止原因、真实后端及完整失败分母。大例无解或超时属于结果，不通过放宽候选或删除任务来改变结论。
